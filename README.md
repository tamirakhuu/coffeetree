# CUPPA
Кофе, цайны дэлгүүрийн сайт. Өгөгдлийн сан тал нь Supabase дээр ажилладаг.

## Ажиллуулах
```
npm install
npm run dev
```
Дараа нь зааж өгсөн хаягаар нээгдэнэ.

## Хуудсууд ба шалгалт

`src/pages/` доторх хуудсууд хэрэгтэй үедээ lazy loading-оор ачаалагдана.
Нийтлэг UI нь `src/components/` дотор компонент бүрээрээ тусдаа файлтай.
Өнгө, нийтлэг style нь `src/theme.js`, URL хөрвүүлэлт нь `src/routing.js`,
өгөгдлийн context нь `src/context/DataContext.jsx` дотор байна.
Туслах функцууд `src/utils/`, салбарын мэдээлэл `src/data/` дотор байрлана.
Сагс болон төлбөрийн төлөв `src/App.jsx` дотор байна.

```sh
npx playwright install chromium
npm run test:smoke
```

Энэ шалгалт production build дээр 18 хуудас, lazy loading, navigation,
сагс болон захиалга → QPay → баталгаажуулалтын урсгалыг туршилтын API
өгөгдлөөр шалгана. Бодит захиалга, төлбөр үүсгэхгүй.

## Удирдлагын хуудсууд
- admin-panel.html — бараа, захиалга, брэнд удирдах хуудас
- aguulah.html — агуулахын ажилтны хуудас
Эдгээрийг угсрах шаардлагагүй, хөтчөөр шууд нээж болно.
## Тохиргоо

Бүх SQL шинэчлэлтийг `supabase/run-all-updates.sql` файлд нэгтгэнэ.
Supabase SQL Editor дахь одоогийн **run-all-updates** query-г ашиглана;
өөрчлөлт бүрээр тусдаа query эсвэл migration файл үүсгэхгүй.
Хэмжээ, бөөний үнэ, Jack's Coffee-ийн хоёр хэмжээний багана, шалгалтын trigger,
захиалга/нөөцийн функцүүдийг хамт шинэчилнэ. Дахин ажиллуулж болно.
Таны өгсөн Supabase `run-all-updates`-ийн админы эрх, storage policy,
Realtime, агуулах, хүргэлт, и-баримтын тохиргоог энэ файлд нэгтгэсэн.
SQL Editor дахь одоогийн **run-all-updates** query-ийн агуулгыг энэ файлын бүтэн
агуулгаар солиод хадгалж ажиллуулна. Тусдаа query үүсгэх шаардлагагүй.
Бараа, захиалгын мөрүүдийг устгахгүй. Хуучин `алдартай` / `эрэлттэй` шошгыг
`бестселлэр` болгоно. Дэд ангиллуудыг устгаж дахин үүсгэхгүй, зөвхөн дутууг нэмнэ;
өөрийн оруулсан ангиллын дүрсийг хадгална. Нөөц хасах хуучин давхардсан
функцүүдийн оронд хэмжээ/агуулахын нөөц тооцох сүүлийн хувилбарыг ашиглана.
Supabase query-д үүнээс хойш нэмэлт өөрчлөлт оруулбал мөн энэ файлд нэгтгэнэ.
`supabase-schema.sql` нь хүснэгтүүдийг устгаж шинээр үүсгэдэг тул одоо ашиглаж буй
өгөгдлийн санд migration-ийн оронд ажиллуулж болохгүй.

Админ → Бараа → Jack's Coffee / Кофе барааг засах → **1кг / 250гр хэмжээгээр зарах**.
Хоёр хэмжээний үнэ, бодит нөөцийг тус бүр оруулж хадгална. Хуучин нөөцийг автоматаар
хуваахгүй, хуучин ширхэг/хайрцгийн үнэ болон бөөний үнэ хэмжээний сонголтод үйлчлэхгүй.
Идэвхжүүлсний дараа захиалгын түүх, нөөц буцаалтыг хадгалахын тулд хэмжээг устгахгүй;
борлуулахаа зогсоох хэмжээнд нөөц 0 оруулна. Хэмжээний нөөцийг админаас засна;
агуулахын хуудсанд хоёр үлдэгдлийг харуулна. Өөр хэрэглэгч захиалга өгч нөөц өөрчилсөн
байвал хуучирсан админ форм хадгалагдахгүй: мэдээллийг дахин ачаалж формыг нээнэ.

`node scripts/test-admin-discount.mjs`, `node scripts/test-bulk-pricing.mjs`,
`npm run test:smoke` нь админ, үнийн тооцоо, сонголт/сагс/checkout-ийг шалгана.
`supabase/tests/coffee_sizes.sql` нь migration хийсэн туршилтын санд ажиллуулах
SQL шалгалт: тусдаа нөөц, захиалгын үнэ, хүрэлцэхгүй нөөцийн rollback, хуучин
барааны урсгал болон брэндийн хязгаарлалт. Бүх туршилтын өгөгдөл rollback хийгдэнэ.
Тусгаарласан локал PostgreSQL шалгалтыг түр хавтаст суулгасан PGlite ашиглан
`node scripts/test-coffee-sql.mjs <PGlite-package-directory>` гэж ажиллуулж болно.
PGlite нь вебсайтын dependency биш.

`supabase-schema.sql` тусдаа үлдэнэ — зөвхөн шинэ сангийн анхны бүтцийг үүсгэнэ.

## Сургалтын хуваарь

Шинэчилсэн `supabase/run-all-updates.sql`-ийг одоогийн Supabase **run-all-updates**
query-д нэгтгэн ажиллуулсны дараа админ → **Сургалтын бүртгэл → Өдөр нэмэх**.
Сараа сонгоод зөвхөн Бямба/Ням гарагийн огнооноос сонгож, **одоогийн сул суудлын тоо**
оруулна. Энэ нь нийт багтаамж биш; өмнө бүртгүүлсэн хүмүүсийг хассан бодит үлдэгдэл.
Бүртгэл нээлттэй өдрүүд хэрэглэгчид харагдана. 0 суудалтай өдөр сонгогдохгүй;
хаалттай өдрүүд харагдахгүй. Хэрэглэгчийн хуваарь 30 секунд тутам шинэчлэгдэнэ.

Шинэ бүртгэл үүсэхэд (төлбөр хүлээгдэж байгаа үед ч) нэг суудал захиалагдана.
Админ тэр бүртгэлийг устгавал суудал буцна. Өмнөх бүртгэлүүдийг өөрчлөхгүй бөгөөд
тэднийг устгахад шинээр тохируулсан үлдэгдэл автоматаар нэмэгдэхгүй. Төлбөр хийгээгүй
бүртгэлийг автоматаар хугацаа дуусгаж устгахгүй. Нэхэмжлэл дахин оролдоход давхар
бүртгэл үүсгэхгүй. Нээлттэй админ формын суудал өөрчлөгдвөл хуучирсан утгаар
хадгалахыг хориглоно; хуваариа шинэчилж, засах цонхыг дахин нээнэ.

Сургалтын SQL мөн энэ нэг файлд байрлана; нэмэлт query хэрэггүй.
`node scripts/test-admin-training.mjs` нь админ формыг шалгана.
`npm run test:smoke` нь Бямба/Ням сонголт, сул суудал, төлбөрийн дахин оролдлогыг;
`node scripts/test-coffee-sql.mjs <PGlite-package-directory>` нь сургалтын суудал,
давтан бүртгэл, хуучин өгөгдлийн хадгалалт болон эрхийн шалгалтуудыг хамт ажиллуулна.
